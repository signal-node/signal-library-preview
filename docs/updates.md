# 更新と復旧

作業を区切り、実行中のOCR/台帳更新がないことを確認する。原本、library.json、書籍台帳、採用版、run/review/exportのIDとhashを保存先で検証する。Dropboxを使う場合は同期を確認し、別の空フォルダへ再取得した内容を照合する。これは追加保存サービスを必須にする指示ではない。

新しいコードは別フォルダへ展開するか、Gitで変更点を確認して更新する。mise.local.tomlを上書きしない。mise設定を更新した場合は内容を確認して信頼し直す。OCR extraを更新するなら新しい仮想環境へ固定constraintsで導入し、doctor/validateで確認する。

ライブラリschemaの自動移行は初期化に含めない。未知schemaは停止し、対応する移行手順が出るまで書込みを進めない。中断処理は記録した同じ計画から再開する。古いコードが新しいschemaへ書けるとは仮定しない。

元版/資材/rendererが変わったらexport statusのstale理由を確認し、別export_idへ再生成する。旧出力と表示確認は保持する。問題があれば新コードでの書込みを止め、保存済みの旧状態と対応コードから確認する。部分更新ファイルを旧コードへ混在させない。
