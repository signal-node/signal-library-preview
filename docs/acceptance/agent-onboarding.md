## 実施するシナリオ

個人実資料・秘密を含めない新規cloneと人工資料を使う。Agent/OS/version、commit、初期設定、実行command、返ったID、失敗/再開、終了状態を記録する。

1. 保存先だけを指定して依存確認・初期化へ進める。所有者のアカウント/パスを要求しない。
2. キーなしで画像と既存MDを登録・検証する。キー設定は人の端末非表示入力で、ログへ値が出ないことを確認する。
3. OCRは人工応答のオフライン試験を先行し、実送信が必要な場合は対象/規模/設定を具体化して許可を得る。過去の1PNG試験の許可を別画像へ拡張しない。
4. 中断後に別セッションから既存runを確認し、成功済みの再送をせず統合・校正・照合・採用へ進む。
5. HTML/PDFを生成し、旧版判定/新ID再生成と原本/旧出力保持を確認する。I-08/09の表示証拠は対象hashに固定したまま保持する。
6. Dropboxを使う試験では人工ライブラリのクラウド同期と再取得を確認し、ローカル保存/コピーと区別する。

認証や実端末が不足する場合、必要な利用者操作を具体化し、他の検証/公開準備は先に進める。未実施のAgent/OSを説明の変更だけで受入済みにしない。

## 回収済み人工OCRの独立2セッション受入

公開dev1（b143c54）の独立clone、Codex CLI 0.163.0/ChatGPT認証、人工PNG2枚と保存済み模擬OCRを使用。承認済み2セッションを実施し、別thread ID、正常終了、共通CLI結果と実ファイルを試験者が検証した。実Mistral通信はない。

初回は台帳から既存runを解決し、rebindで旧manifestを履歴保存。新しいreading-agent-001に7要件を適用した。原画像/raw/旧本文/旧校正版とIDを保持し、未照合・未採用を維持した。次回は同じ台帳から再開し、原画像の「保持する。」に対するOCR誤り「保持すろ。」を新revisionで訂正。日本語本文4範囲だけをtext照合として記録し、revision-agent-001を採用した。本文と整形計画が同一のrevision-agent-002を追加しても、照合記録は継承せず未照合、採用版は001のままだった。validateと読取り専用の採用計画を試験者も確認し、後者で資料が変わらないこともhashで検証した。
