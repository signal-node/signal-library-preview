# 確認環境と未確認事項

0.1.0の確認環境と継続して追跡する課題を示します。macOS/WindowsネイティブとCodex/Claude Codeを対象にしていますが、以下の確認範囲には差があります。未確認の組合せは実験的対応です。

## 確認した範囲

| 項目 | 確認内容 |
| --- | --- |
| 共通CLI | macOS/Windows/LinuxのCIで人工資料による登録、OCR模擬通信/回復、整形/版管理、HTML/PDFと配布を検証。初版候補の実施状況は[受入判定](acceptance/release-0.1.0.md) |
| macOS Codex | キーなし初期化/画像・MD登録、別セッション再開、HTML/PDF生成。回収済み人工OCRの再接続、7要件整形、新revision、本文4範囲照合/採用と新版の未照合維持 |
| OCR実API | 許可した自作PNG1枚のMistral OCR 4.1 Batch送信/回収と原画像比較。任意の書籍の精度や送信許可を意味しない |
| 送信前の案内 | キー未設定の人工1例で非表示入力案内、OCR計画、無許可送信前の停止。不正な書誌内指示を実際に読んで実行しなかった |
| 表示・保存 | macOSで人工HTML/PDFの確認、HTMLのコピー先/オフライン操作確認。人工1冊のDropbox同期/Web再取得、全ファイルhash一致と別root再開 |

## 継続して追跡する未確認事項

| ID | 未確認事項・リスク | 解消時に必要な証拠 |
| --- | --- | --- |
| R-01 | Windows実端末の依存導入、Codex/Claude対話、表示・操作。CI成功だけでは端末固有の権限/フォント/操作を保証できない | OS版/CPU/Agent版を記録したネイティブ端末での新規導入・中断再開・表示操作 |
| R-02 | Claudeの起動/認証/実対話、Codexとの切替。入口の静的検査だけでは発見/対話成功を保証できない | Claudeで新規開始/別セッション再開と、台帳を使うAgent間切替。実行には利用者の利用可能な契約/認証が必要 |
| R-03 | 新規Codexによる実キー設定から新規実OCRまでの一巡、外部job状態不明からの実対話。個別構成要素を組み合わせた導入時の問題が残り得る | 対象別の送信許可、利用者自身の非表示入力、実API/Agent/台帳の対応記録。既存jobの確認と二重送信しない再開 |
| R-04 | 完全に空のユーザー設定を持つ第三者端末での導入。開発者端末にあるツール/設定の影響を完全には除けない | 所有者設定に依存しない新規端末の記録と不足依存の案内 |
| R-05 | 任意の書籍全体のOCR/整形品質、数式/図表の正確さ。人工資料と部分照合は全文照合ではない | 利用する範囲を原画像と比較し、版と位置を固定した照合を記録 |
| R-06 | 実キーが存在する状態の動的な非漏洩と一般的な指示注入耐性。人工書誌1例の成功を一般化できない | 秘密を公開せず、試験用値と多様な入力/権限条件で境界を検証。資料内指示を権限と扱わない運用を継続 |

R-01〜03の実対話受入は、未確認であることを明示して初版後へ送ることを承認済みです。未実施を合格としたものではありません。契約購入やWindows機の用意を利用者に要求しません。新たなAI/API利用・第三者への連絡は自動で行いません。

Windowsの最低OS版・CPU構成、全ブラウザ/全端末への互換性は保証していません。使用する依存版は[設定手順](setup.md)を参照してください。

## 初版の対象外

同じ保存先への複数端末同時書込み、複数captureの自動本文統合、Notion/NotebookLMへの搬送、Gemini TTS。Dropboxは単一端末＋Web再取得の限定試験であり、同期競合や通信断の全条件を検証したものではありません。

API見積りは請求の強制上限ではありません。キーはローカル設定へ平文保存され、Git除外でもクラウド同期され得ます。新しい出力や版へ過去の照合/表示確認を継承しません。[障害報告](../SUPPORT.md)、[詳細な受入記録](acceptance/agent-onboarding.md)を参照してください。
