# 統合本文・校正版Markdownの整形要件

決定日: 2026-10-06（JST）。利用者指定の7要件を初版のI-07へ追加する。以下は実装・受入の仕様であり、現在の統合ツールが対応済みという意味ではない。

## 対象と保存

読書用の統合Markdownと校正版へ適用する。原画像・元OCR・旧revisionは保持し、整形のために上書きしない。本文の意味や原典の構造を保ち、変更箇所・理由・原本位置を追跡できるようにする。整形が済んだことと原典照合済みであることは別に記録する。

## 必須要件

| 要件 | 処理と完了条件 |
| --- | --- |
| 1. 各ページのヘッダ・フッタを残さない | 柱、繰返しの書名・章名、紙面ページ番号等を読書本文から除去する。章本文の見出し、脚注、図表のキャプションは残す。紙面番号・原画像への対応は台帳・ページ対応記録へ保持する |
| 2. MD全体で見出し構成を揃える | 書籍の章・節・項の構造に合わせて見出しレベルの対応を定め、全対象範囲で統一する。ページごとに階層を再開始しない。本文を見出しへ昇格したり、存在しない章・節を補ったりしない |
| 3. 段落を揃える | 原典の論理段落を保持し、段落間は空行で区切る。同一段落のOCR由来の不自然な分断を修正する。箇条書き、引用、脚注、数式、コード等の構造を段落統一のために壊さない |
| 4. 図は画像として挿入する | 対応する図の画像を保存し、Markdown画像記法と相対参照で本文の該当位置へ挿入する。キャプション・図番号を保持する。文字だけの説明で図を代替しない。図の欠落や判読不能は要確認として残す |
| 5. 表はMDの表で挿入する | 表の見出し、行列、セル値、単位、表番号・注記を保持してMarkdown表へ変換する。画像だけの表で完了扱いしない。結合セルや多段見出しは対応関係を保つ展開方法を原典と照合する。忠実な変換が未解決なら要確認として残す |
| 6. 日本語の読点は「、」に統一する | 日本語本文の読点として使われている「，」や「,」を「、」へ統一する。インライン・独立行の数式内は変換しない。コード、URL、参照先、数値の桁区切りや英語の句読法等は日本語の読点と区別し、無差別な全置換をしない |
| 7. 文中の改行を一文にまとめる | OCRの紙面折返しやページ境界で分断された同一文を結合する。日本語文字間へ不要な空白を入れない。欧文の単語境界には必要な空白を保持する。論理段落・箇条書き・詩等の意図的改行、数式の改行は保持する |

見出しの統一は、まず書籍全体または対象範囲の見出し一覧を確認してから適用する。部分章の校正でも、同じ書籍の他の章と共通の対応を使用する。段落統一は原文の全段落を一段落へまとめる指示ではない。

ページ別の出典情報は失わない。ページ由来の区切りやメタデータを、章・節の見出しとして混ぜない。継続する文を結合した場合は、両ページの原本位置を対応記録へ残す。

## 処理とレビュー

原画像・OCRの対応確認→見出しと段落の構造確認→ヘッダ/フッタ除去候補の確認→図画像・表の復元→日本語読点と文中改行の整形→差分・原典照合→新revisionと確認記録、の順で進める。

共通CLIは変更差分、参照、対応記録、形式検査を担当し、Agentは原画像との比較と構造判断を支援する。確信のない削除・結合・表の展開は候補として示し、needs_reviewに残す。繰返し文字列であることだけを根拠に本文を削除しない。整形規則やモデルの判断だけでverifiedにしない。

完成した整形本文は7要件を満たす。未解決箇所のある出力は未完了/要確認として示し、処理成功だけを整形完了と扱わない。図の欠落、表の未変換、ヘッダ/フッタ候補の残存等を無言で省略しない。

## 受入と反証

人工fixtureと原典比較で次を確認し、反証になる入力も含める。

- 同じ書名が柱と本文に現れる入力で、柱だけを除去し本文を保持する。ページ番号は本文から除去して対応記録へ残す。脚注・キャプションは削除しない。
- 同じ階層の見出しがページごとに異なるレベルでOCRされても、全体で一致する。ページ区切りを章として数えない。
- 日本語の紙面折返し・ページをまたぐ一文は結合する。一方で別段落・箇条書き・数式の改行を結合しない。欧文単語が連結されない。
- 図はローカル画像として表示でき、図番号・キャプション・参照位置が一致する。欠落を成功扱いしない。
- 通常表と多段見出し/結合セルの表で、MDのセルと原典の対応を確認する。画像だけに退避して完了にしない。
- 日本語本文の読点は「、」となり、数式 `$f(x,y)$`、数値 `1,000`、コード、URL等は保持される。数式内の「，」も読点統一の対象にしない。
- 整形前後で原画像・元OCR・旧revisionのhashが変わらず、削除・結合箇所の原本位置と変更理由を確認できる。
